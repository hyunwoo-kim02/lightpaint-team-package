1. 전체 파이프라인

현재 구현은 “경로 생성 → PID baseline → RL residual 보정 → LED/paint 누적 → reward/eval” 구조다. RL이 raw motor RPM을 직접 배우는 구조가 아니라, 이미 있는 reference 추종 제어 위에서 보정량을 학습한다.

LightPaintRef / letter skeleton
        ↓
reference state: p_ref, v_ref, yaw_ref, led_ref
        ↓
Phase A: PID(p_ref, v_ref) + scripted LED
Phase B: PID(p_ref, v_ref + delta_v) + clipped(led_ref + delta_led)
        ↓
PyBullet physics / standalone physics
        ↓
progress_mask, cumulative paint, reward components, info diagnostics
핵심 해석: Phase A는 학습 라벨을 생성하는 데이터셋이 아니라, Phase B가 “zero action일 때 돌아와야 하는 baseline 동작”이다.

2. Phase A/B/C 의미

구분 목적 Action space 외란 현재 상태
Phase A PID + scripted LED baseline sanity/regression Box(0, 0, shape=(0,), dtype=float32) M0만 허용 기준선. 깨지면 Phase B 학습 신뢰 불가
Phase B velocity residual + LED residual 학습 Box(-1, 1, shape=(4,), dtype=float32) M0/M1/M2 사용 가능 현재 RL 학습/강건성 실험 대상
Phase C 이후 고수준 LED/경로 정책 확장 후보 discrete/continuous placeholder 정책 설계 필요 현재 active A/B 경로 밖

현재 코드상 Phase 구분은 필수다. Phase A와 Phase B는 action shape, wind constraint, action preprocessing, 테스트 계약이 다르다.

3. Reference와 GT의 관계

LightPaintRef 또는 letter skeleton이 실제 기준 경로를 정의한다. 여기서 생성되는 것은 waypoints, 누적 거리, 기준 속도, stroke별 LED 값이다. Phase A는 이 reference를 PID로 추종해 baseline rollout을 만들 뿐, GT 자체를 새로 생성하지 않는다.

  • p_ref: 현재 시각 또는 arc-length 기준 목표 위치
  • v_ref: reference를 따라 움직이는 기준 속도
  • led_ref: target mask 또는 stroke segment 기준 scripted LED
  • segment_led: stroke는 LED on, connector는 LED off로 표현
코너 스무딩 관점에서 중요한 점: 현재 reference가 이미 어느 정도 smoothing을 가질 수 있고, Phase B는 그 위에서 residual로 감속/보정 행동을 배운다. 즉 “reference geometry”와 “RL residual behavior”를 분리해서 봐야 한다.

4. Action 계약

Phase A

RL action이 없다. step에는 np.zeros(0, dtype=np.float32)가 들어가며, PID와 scripted LED만 동작한다.

Phase B

Phase B action은 반드시 4차원이다.

Index 의미 적용 위치 중요 계약
action[0:3] 3축 target velocity residual target_vel = v_ref + delta_v 물리 command에 직접 더하지 않는다. PID target velocity에 들어간다.
action[3] LED residual brightness = clip(led_ref + delta_led, 0, 1) info 기록만이 아니라 실제 painting/update 흐름에 반영된다. 
delta_v   = action[0:3] * RESIDUAL_DELTA_MAX
delta_led = action[3]   * LED_RESIDUAL_SCALE

target_vel = v_ref + delta_v
rpm = DSLPIDControl(..., target_pos=p_ref, target_vel=target_vel)

brightness = clip(led_ref + delta_led, 0.0, 1.0)
led_on = brightness > 0.5

필수 invariantaction = 0인 Phase B는 가능한 한 Phase A PID + scripted LED baseline과 같아야 한다.

5. Observation 계약

PyBullet과 standalone은 공통적으로 Dict observation을 쓴다. 학습 코드는 이 key와 shape에 의존한다.

Key Shape 의미
drone_state (12,) position, velocity, attitude, angular velocity의 정규화 상태
future_ref (45,) 미래 reference point 15개 × 3축
target_mask (1, 64, 64) 그려야 하는 static target mask
progress_mask (1, 64, 64) 현재까지 실제로 칠한 누적 mask

Gymnasium API는 reset() -> (obs, info), step(action) -> (obs, reward, terminated, truncated, info) 계약을 따른다.

6. PID와 RL residual의 역할 분리

PID가 담당하는 것

  • reference position과 velocity 추종
  • PyBullet에서는 DSLPIDControl.computeControlFromState로 RPM 산출
  • Phase A baseline과 Phase B zero-action 기준 형성

RL residual이 담당하는 것

  • 코너에서 속도/방향 residual 보정
  • M1/M2 외란에 대한 강건성 보정
  • LED on/off timing residual 보정
  • 과도한 action 변화는 reward penalty로 억제

중요한 점은 Phase B가 “PID를 버리는 학습”이 아니라 “PID target을 수정하는 학습”이라는 것이다. 따라서 정책이 잘못 학습되어도 baseline으로 돌아갈 수 있는 zero-action anchor가 있다.

7. LED와 painting update

LED는 led_ref + delta_led로 계산된 brightness를 사용한다. 현재 painting 판정은 binary threshold 기준이다.

  • brightness = clip(led_ref + delta_led, 0, 1)
  • led_on = brightness > 0.5
  • led_on == true일 때만 progress mask에 stamp한다.
  • paint metric은 target 위 신규 도색, target 밖 도색, repaint를 분리한다.

이 설계는 “LED residual을 info에만 기록하는 fake 구현”을 피한다. 실제 progress_mask, reward, coverage 진단에 반영된다.

8. Reward shaping

현재 reward는 과하게 복잡한 최종 논문용 metric이 아니라, 학습이 망가지기 쉬운 행동을 막는 최소 shaping 항목으로 구성되어 있다.

Reward component 의미 유도/억제 행동
r_path reference path에 가까울수록 보상 경로 이탈 억제
r_schedule 현재 시간의 p_ref에 가까울수록 보상 무한히 천천히 가거나 멈추는 행동 억제
r_led_target target 위 신규 도색 보상 필요한 곳을 실제로 칠하도록 유도
r_led_off target 밖 도색 penalty 원하지 않는 선/번짐 억제
r_repaint 이미 칠한 곳 재도색 penalty 같은 픽셀 반복 도색 억제
r_smooth RPM 또는 final command 변화 smoothness 제어 진동 억제
r_action_mag, r_action_rate residual 크기와 변화율 penalty PID baseline을 불필요하게 크게 훼손하는 정책 억제
r_led_flicker brightness 급변 penalty LED 깜빡임 억제
r_corner_speed 코너 sharpness가 클 때 과속 penalty 코너에서 자연스러운 감속 학습 유도
r_terminal out-of-bounds penalty 비행 영역 이탈 억제
코너 스무딩은 별도 “정답 trajectory”만으로 해결되는 것이 아니라, path 유지 + schedule 유지 + corner speed penalty + residual smoothness가 함께 작동하면서 학습될 수 있는 구조다.

9. 외란 모델

Mode 현재 의미 학습/검증 용도
M0 zero force Phase A PID sanity baseline
M1 episode마다 수평 방향/크기를 샘플링한 constant world-frame force 기본 외란 강건성 smoke/regression
M2 수평 방향은 고정, magnitude는 sinusoidal gust 시간 변화 외란에 대한 residual 보정 검증
M3 placeholder 현재 필수 구현 범위 밖

PyBullet env에서는 rotor physics 이후 p.applyExternalForce(..., flags=p.WORLD_FRAME)로 외란을 실제 physics에 적용한다. standalone env는 numpy physics에 force를 반영하지만 fidelity는 PyBullet보다 낮다.

10. PyBullet vs standalone/fallback

항목 PyBullet env Standalone env
파일 src/env/light_paint_aviary_pyb.py src/env/light_paint_aviary_standalone.py
목적 production physics/evaluation 기준 PyBullet 없이 빠른 smoke/fallback
제어 Crazyflie CF2X + DSLPIDControl + RPM numpy PID velocity command + 간단 physics
Phase B 계약 target_vel = v_ref + delta_v 동일 계약으로 맞춤
학습 결과 보장 실제 기준 동일 결과 보장 없음. smoke와 빠른 디버깅용
standalone으로 학습한 정책이 PyBullet에서 동일하게 동작한다는 보장은 없다. 둘의 공통 계약은 맞추되, 최종 판단은 PyBullet에서 해야 한다.

11. 회귀 테스트가 보장하는 것

  • Phase A env reset/step smoke와 Gymnasium API 계약
  • Phase B action space가 Box(-1, 1, shape=(4,), dtype=float32)임
  • Phase B zero-action이 PID/LED baseline과 일치함
  • Phase B nonzero action이 target_vel과 LED brightness에 실제 영향을 줌
  • step(action)이 PyBullet _preprocessAction까지 action을 전달함
  • M1/M2 외란이 nonzero force를 만들고, PyBullet에서는 WORLD_FRAME으로 적용됨
  • standalone fallback도 Phase B residual 계약을 따른다
  • visualization frame directory가 stale frame을 섞지 않는다

13. 운영 체크리스트

  • Phase B 학습 전 Phase A baseline regression이 깨지지 않았는지 확인한다.
  • Phase B 정책 평가 시 action=0 baseline과 nonzero residual 효과를 분리해서 본다.
  • 외란 robustness는 최소 M1, M2에서 smoke 후 긴 학습으로 넘어간다.
  • LED 성능은 led_on, brightness, paint_new_target, paint_off_target, paint_repaint를 함께 본다.
  • fallback env 결과를 최종 성능으로 해석하지 않는다. PyBullet 결과가 기준이다.
